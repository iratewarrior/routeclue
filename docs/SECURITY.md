# Security Notes

## What RouteClue protects

- **Leak on tunnel failure.** If the tun interface disappears, the default route returns to the
  physical interface. The generated PF ruleset in `com.apple/routeclue` allows only the tunnel core,
  private ranges, the optional allow-list and explicitly configured DNS servers; every other outbound packet on `en*` is
  dropped.
- **Stale routes after switching networks.** Routes are recreated against the gateway that is
  actually in use, with `-ifscope`.
- **Wrong source address.** `-ifscope` prevents packets from leaving with the tunnel's address,
  which corporate networks drop.
- **Private name resolution.** Scoped resolvers in `/etc/resolver` keep internal zones on internal
  DNS instead of leaking queries to a public resolver.
- **No destructive firewall overwrites.** The kill switch uses the isolated anchor `com.apple/routeclue`.
  It does not overwrite `/etc/pf.conf` and does not run global `pfctl -F all` or `pfctl -d`.

## Limitations & Disclosures

- **It is not a VPN.** No encryption and no transport. It shapes routes and firewall rules around a
  tunnel you already run.
- **Root processes bypass the kill switch.** The allow rule is `user = 0`. Anything running as root
  (including the VPN daemon) can still reach the network directly. This is by design to avoid hardcoding
  VPN server IP addresses.
- **Pre-existing connection states.** Connections established before activating the kill switch
  may persist until their states expire or are flushed.
- **IPv6 management limits.** IPv6 traffic is blocked on physical interfaces (except for ICMPv6 Neighbor
  Discovery and root), but RouteClue does not configure IPv6 routes.
- **A hostile kernel or compromised client** is out of scope.
- **Corporate policy.** Using a personal tunnel alongside a corporate network may violate policy.
  This tool does not change that.

## Privileges

Privileged commands execute through the macOS authorization dialog (`osascript … with
administrator privileges`). Nothing is stored, no root helper stays resident, and no LaunchDaemon is
installed. The ruleset is validated with `pfctl -n` before loading, so malformed rules fail closed.

Restoring firewall state safely without affecting other applications:

```bash
routeclue killswitch off
```

## Files touched

| Path | Purpose |
|---|---|
| `~/Library/Application Support/RouteClue/config.json` | Configuration |
| `/var/run/routeclue/pf-token` | Active PF reference token |
| `/etc/resolver/<zone>` | Split-DNS files (with `# Generated by RouteClue` ownership header) |
| routing table | `-ifscope` routes for configured subnets |
| PF `com.apple/routeclue` | Isolated anchor rules while kill switch is on |

## Reporting

Open an issue with the output of `routeclue doctor` (it contains no credentials) and the exact
macOS version.
